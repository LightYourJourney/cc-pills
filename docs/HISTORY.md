| # | 发现 | 等级 | 证据 |

| A1 | subagent 文件多时 token 助手永久不出数 | 高 | 主循环对每个文件无条件落盘，1 s 预算耗在已追平的文件上。合成会话（去重表满）约 75 个 transcript 文件即触发，N=100 连续 30–60 次调用无输出 |
| A2 | 后台刷新状态机与增量扫描没有测试保护 | 中 | 8 个单点变异（git 缓存 TTL / HEAD 失效、残锁接管、色板退避、状态页过期、逐片落盘、尾部指纹、TOK_MIN_GAP）全部存活 |

| A4 | 配置末行没有换行符时被静默丢弃 | 低 | 渲染脚本与 doctor 的解析器错得一致，doctor 报「可解析」 |

| A6 | 一条 doctor 用例依赖仓库是 git 检出 | 低 | 从 zip 解出的源码树跑测试会失败 |
| A7 | `step = drop today` 被静默忽略 | 低 | `ITEM_IDS` 折行书写，行尾的 `today` 后面是换行；做 `--facts` 时才暴露（doctor 此前按另一种方式取名单，一直报通过） |

实测数据（本机 arm64 / bash 5.3 / python 3.15，hyperfine）：同步渲染 220 列 17.8 ms、90 列
19.3 ms，其中 bash 启动约 6 ms、jq 约 4.8 ms；后台刷新空转 11 ms、3 次 fork。153 MB 主
transcript + 200 MB subagent 整段重扫 0.54 s。

未验证、留作已知风险：中转站模式下 `st['unl']` 在消息始终不入账时无上界（需要真实中转站
数据）；`subagents/workflows/*/*.jsonl` 只匹配一层（本机没有 workflow 样本）；Linux 且未设
`TMPDIR` 时同机其他用户可抢占 `/tmp/claude-sl-<uid>` 使状态栏永久无缓存（仅降级，doctor 报
FAIL）；面板抢锁在输出之后，竞争时进程最多晚 1 s 退出。
