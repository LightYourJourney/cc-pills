# 设计裁定与沿革

脚本头部只留「改代码时必须知道的契约」。这份文件记录**为什么长成这样**：每次外观改版、
每项去留的裁定、做过又否掉的假设。改外观或降级序列前先读这里，免得把已经否掉的方案
再提一遍。

日期均为 2026 年。

## 架构

- **08-19 方案 C**：同步路径只读缓存 + 后台刷新算慢的（git / transcript / 配色 / 状态页）。
  当时的目标是 <20 ms；10-28 实测中位约 18–22 ms（视降级步数）。
- 同步路径只允许一次 jq；宽度计算与组装全在 bash 内建完成（约束 17）。
- **状态文件带版本**：`$SLT/claude-statusline-<sid>.json` 只认文件自身的 `v`；与 `STATE_V`
  不符即整体重扫（分片、后台），旧结构不会被当成新结构读。v9 把每文件消息数键改为
  `last_id` / `msgs`。
- **缓存目录私有化**（10-29）：默认 `${TMPDIR:-/tmp}/claude-sl-<uid>`（0700），文件 0600；
  读取前用 bash 内建 `-O` 校验所有者，跨用户预置的同名文件一律不读；临时文件用 `mktemp`
  （O_EXCL），Python 侧用 `mkstemp`。旧版 `/tmp` 的本会话 token / 状态 / 跳过标记在首次
  刷新时迁入私有目录。缓存内容按不可信数据处理：token 字段剔除控制字符，色板值只接受
  数字与分号，git 状态也剔除控制字符。显式 `CLAUDE_SL_TMP`（预览 / 测试）由调用方负责
  隔离，且目录必须已存在——渲染不会代为创建（doctor 判 FAIL）；旧 `/tmp` 里的历史文件不
  自动删除（过渡期残留，由系统清理或用户手工删）。
- **token 缓存新鲜度**（10-29）：生产者写 `<cache>.ts`；同步路径超过 `TOK_STALE=900` 秒
  不读派生值（$/h、out、等级、hit、io、msgs、comp），本轮只保留 stdin 的额度百分比，
  等下一轮刷新补上。没有 `.ts` 的旧缓存 / 预览假缓存按新鲜处理；从旧版本迁移来的
  缓存由刷新按它自身的 mtime 补一次 `.ts`（否则「无时间戳 = 新鲜」会让旧值永久留存）。另加窗口一致性护栏：
  当前 q5 / q7 / sp < 100 时，缓存里的「用尽」不可能属于当前窗口，直接丢弃该等级与
  out；`bad` + 真实倒计时（「很快用完」）保留。
- **18 段 token 缓存的字段顺序以 `statusline-tokens.py` 的 `FIELDS` 为准**：生产者按字段名
  填、按 `FIELDS` 输出；bash 的 `IFS=tab read`、测试与 `tools/preview.sh` 的假数据由
  `tests/test_tokens.py` 的契约测试守护。改顺序只动 `FIELDS` 与 `BASH_NAMES`。

## 外观沿革

| 版本 | 做法 | 结果 / 为什么被替换 |
|---|---|---|
| 早期 | 每组一种底色、告警时整块变色 | 同屏常有 4 个彩色胶囊，喧宾夺主 |
| 第七版 | 中性底，按 14% 混入 profile 背景 | iTerm 透明度只提亮默认背景（#1e1f29 → 实测 #272a36），胶囊几乎融进背景 |
| 第八版 | 全部同一种字色 | 相邻两项、相邻两胶囊都分不开 |
| 第九版（现行） | 统一表面色 + 标签着色 + 三级信息层次 | 主次分明；胶囊底色统一时靠文字层级区分 |

## 外观裁定

- **标签着色 + 主次分层**（10-28）：标签用组色（ctx 绿 / 额度紫 / 费用青 / 尾段弱化），
  降饱和、避开黄红色相，彩度封顶在告警色的 75%；主值加粗；语义色只给需要注意的那一项。
- **胶囊风格做成配置项**：先做了 A–F 六种（tint / cool / jewel / glass / mono / pastel），
  看完 iTerm 实渲染预览后全部保留为 `pill_style` 的可选值，默认 `tint`。
- **tokyo-glass**：融合 B/C/D 三种方案——Tokyo Night 冷色 token、贴近背景的玻璃胶囊、
  三级层次；模型名冷蓝、费用降为二级不加粗、hit/io/api 降为三级。告警分两档：80–94%
  柔和红，≥ `crit_at`（默认 95）或很快用完为强红。
- **胶囊底色与背景的可辨距离只约束基础表面色**（`MIN_PILL_DE = 12`）：各风格的组胶囊
  明度 / 彩度由风格定义，不再逐组套这道门槛。原因是逐组提亮会把风格设计的明暗节奏
  抹平（外观裁定优先于统一门槛）。
- **中灰底上 7:1 无解**：主值退到 `MIN_CONTRAST = 4.5`（WCAG AA）。10-28 对比度矩阵复测
  时发现中灰底上文字极性判错（浅字压在亮胶囊上只有 3.76），已改为按胶囊实际明暗定极性；
  4.5 这条下限不再退让。

## 信息项去留

- **永不丢弃**：dir、git、gitst、model、ctx、ctxin、q5、cache、hit、io。
- 其余项按「降级序列」逐步丢弃 / 缩短；额度进入风险态时其 drop 步骤自动失效——免得
  只剩一个看不出属于谁的「out 1h42m」。
- `misses` 不显示（无效信息）；墙钟时长不显示（含空闲时间），只显示 `api` 累计时长。
- ctx 阈值 70 / 90 与额度阈值 50 / 80 分开：ctx 是「快满了该压缩」，额度是「用得多了」。
- **面板 ctx 显式标「剩」**（10-29）：主栏 ctx 是**已用**（70 / 90 告警），面板由
  tokenCount / contextWindowSize 算出的是**剩余**（<20% ⚠）。两者同叫 ctx 会误读，
  面板改为 `ctx 剩 N%`；数值与阈值不变，不改主栏语义。

## 费用口径

- **自动分模式**：stdin 有 5h / 7d 额度 → 订阅；否则设了非官方 `ANTHROPIC_BASE_URL`
  → 中转站；都没有 → 按订阅处理（订阅会话在首个 API 响应之前还没有 `rate_limits`，
  曾因此被误判成中转站）。
- 订阅显示 `$x`：标价估算的等价价值，不加 `API≈` 前缀。
- 中转站显示 CC Switch 账本 + 未入账尾部；有未计价消息时加 `+` 后缀表示下限。
- 网关 `rate_limits.spend_limit` 存在时优先于 CC Switch 的日限额。
- **「今日花费」按 `app_type = 'claude'` 直查数据库**，不再依赖「渲染过状态栏的会话」列表：
  `claude -p` 等无头会话从不渲染，靠列表会把它们的花费永久漏掉（实测漏了一个 $0.28
  的会话）。Codex 等其它 app_type 不计入，需要看合计时去 CC Switch 用量页。
- **中转站日限额按「当前供应商可归属」口径**（10-29，上游核实）：CC Switch v4.0.21 的
  `check_provider_limits`（`src-tauri/src/services/usage_stats.rs`）把今日用量算成
  `proxy_request_logs` + `usage_daily_rollups` 中 `provider_id = 当前供应商` 的和；限额读
  `providers.meta.limitDailyUsd`（旧库的 `limit_daily_usd` 列已不被上游读取）。
  `provider_id = '_session'` 是会话日志的哨兵（`session_usage.rs`），上游也不把它归给任何
  供应商。故日限额的分子只算当前供应商可归属的今日；全局「今日」仍按 app_type 汇总。
  没有 / 多个 `is_current`、限额值非法或为 0 时隐藏日限额项与预测——未知不能当 0；供应商
  切换时 day 追踪器按（本地零点, provider_id）重置。上游此版本没有额度强制与 UI 消费
  （`useProviderLimits` 只有定义），所以它是只读提示，不是硬预算。展示层在有日限额时
  只显示当前供应商可归属的 `$cur/$限额`；全局今日由无日限额时的 today 项显示，
  不可归属 = global − cur 由返回值与测试固定。日限额项**不加**「仅供应商」标记——
  那需要新增第 19 段并版本化缓存，本次按「不改 18 字段协议」的裁定留作后续。
- **已用 ≥ 100% 判最高级并显示「用尽」**，不再显示可能为负的「还剩」。

## 速率与缩略（10-28 第二轮）

- **$/h 半衰期 600s → 1200s**。用本会话 601 条账本逐分钟重放：600s 时单笔大请求会让读数
  一分钟内跳 $14（一天 2 次 >$8），1200s 把最大跳变压到 $7.2、>$8 的跳变归零；代价是
  达到 90% 的时间从约 30 分钟变成约 50 分钟。**滑动窗口被否**：15 分钟窗反而更跳（单笔
  花费进出窗口即阶跃，>$3 跳变 8 次），30 分钟窗与 20 分钟 EWMA 相当但反应更慢。
- **第三方模型名缩略**：无空格的名字取首个 `-` 段并保留方括号上下文标记
  （`deepseek-flash[1M]` → `deepseek[1M]`，`gpt-6.1-sol` → `gpt`）。已知代价：同一家族的
  flash / pro 会缩成同一个名字，宽屏下仍显示全名，只有窄屏最后一级受影响。
- **宽屏填充只加消息数**（`m517`）：会话开始时刻、git 领先/落后都被否；墙钟时长维持
  早先「不显示」的裁定。
- **去掉「今日」标签**：会话费用、当前速率、今日合计依次相邻，标签是冗余；日限额与今日
  合计都改为只显示 `$x` / `$x/$限额`。`day` 项因此只剩一种写法，随之删掉 `shrink day`
  这一步。网关 `spend_limit` 的「今日 / 本周 / 本月」保留——那里标签表示周期。

## 被否掉的假设

- **「两源重复记账」**：15 个两源并存的会话逐条比对，残余重复为 0。两源（代理行、
  会话日志行）互补，不需要额外去重。
- **「会话日志滞后 9 小时」**：实为使用者空闲；日志每 10 分钟同步。
- **`prompt_cache.warm = false` 就判冷**：官方说明里 `warm=false` 也包括「最近一次响应
  没报告缓存 token」，所以只在 `expires_at` 已过时判冷。

## 交互与工具

- **预览工具必须隔离**：早期版本把伪造的「claude major」写进全会话共享的状态缓存，
  所有窗口跟着显示，而且旧的「上次拉取时刻」会让预览要等 30 秒。现在每次预览用独立
  缓存目录 + 假数据，跑完即删。
- **fit 回填**：降级时某一步可能一次省出很多列（如缩短长模型名），放得下之后按逆序把
  被牺牲的项恢复回来。
- **git 缓存 TTL 5 秒**：更短的等待换来分支切换后几乎立刻正确；`.git/HEAD` / `.git/index`
  变新时立即重算，不等 TTL。
- **`status_page` 开关**：默认 `on`（每分钟请求 status.claude.com）；`off` 时零网络请求、
  不显示服务状态。给不需要外部请求、或在隔离环境里跑的人用。
- **示例配置不固化默认序列**（10-29）：示例里的 36 条 `step` 全部注释，脚本在没有
  `step` 行时使用内置 `STEPS`；只要写一行 `step` 就整体替换（既有行为）。`--with-conf`
  复制的是注释版，因此未来的默认调整会继续生效；注释里的顺序由
  `tests/test_tokens.py::ConfigProtocol` 与 `STEPS` 对齐。
- **安装器覆盖两个 settings 键**（10-29）：install / check 同时检查 `statusLine` 与
  `subagentStatusLine`；命令必须指向已安装副本（或使用 `${CLAUDE_CONFIG_DIR...}` 的
  官方写法），只是文件名相同、路径不明的命令也按 rc=1 报出。uninstall 删除脚本后只
  警告仍指向已删除文件的键（识别同一组写法），不自动改用户 settings。
- **面板共享状态加锁**（10-29）：状态文件被本机所有会话共享，读-改-写全程持同一把
  `mkdir` 锁，锁内**重新读取**后再合并；抢锁超过 1s 就放弃本次写回（宁少一帧速率，
  也不覆盖别家条目）。残锁 5s 后清除。状态文件默认带 uid（
  `${TMPDIR:-/tmp}/claude-subagent-sl-<uid>.json`）、0600；旧状态不迁移（只有速率基线，
  丢失代价是一帧）。

## 运行诊断（10-30）

- **实现放 `tools/doctor.sh`（入口）与 `tools/doctor/{env,install,cache,data}.sh`（四组检查）**：
  `install.sh --doctor` 只是 exec 别名：install.sh 是写工具（复制 / 备份 / 删除），诊断是读工具；
  分开才能从结构上保证「默认只读」，也不让只读诊断背上安装流程的语义。入口只负责共享状态、
  加载顺序与汇总，每组检查各自演化，避免一个文件因四类无关原因反复改动；模块随仓库提供，
  不写用户目录。别名只加一次 `shift` 与一次 exec，不重复任何逻辑。
- **doctor 保持 bash 3.2 可跑**（不用关联数组）：最坏环境里——PATH 里的 bash 是 macOS 自带的
  3.2——它仍要能回答「为什么状态栏退化成最简行」。渲染脚本本身仍要求 ≥4.2，两者要求不同是
  故意的。
- **五个状态词**：PASS / WARN / FAIL / SKIP / UNKNOWN。SKIP = 不适用（没装、没配、没用到），
  UNKNOWN = 取决于运行时 stdin（例如计费模式），命令行里无法判定。没有「差不多正常」这种
  中间态——那正是本阶段要消灭的表达。
- **FAIL 只留给「状态栏很可能不工作」**：环境依赖（bash / python3 / jq）不满足、安装目录或
  副本缺失、settings 缺失/不可读/非普通文件/语法错误/未指向、缓存根不可用（显式路径不存在、
  符号链接、非目录、不属于本人、不可写）、锁路径被普通文件、符号链接或非空目录占住、显式
  `--transcript` 不存在或不可读、冒烟无输出、最简行、stdin 原文透传、缺少 ctxin/其余字段的
  渲染形态或两份夹具结果相同才是 FAIL。残余的「副本缺失」与「settings 缺失」同时 FAIL 是
  故意的——两处都要修。副本与仓库不一致、配置文件不可读是 WARN（能跑，只是跑的不是仓库那
  一版 / 渲染脚本对 `-r` 失败只是静默用默认值）。
- **判「能不能用」而不是「新不新」**：渲染侧上色的条件是「缓存的主题部分与当前 `theme` 相同
  且有**合法**的 `P_CTX`」（`statusline-command.sh` 的 `NC=0`：值只含 `[0-9;]`，非法值会被
  整条丢弃）；chroma / 风格 / 格式版本不符只会触发
  后台重算，年龄也不影响本轮上色，所以旧色板是 PASS（静止时不上涨是正常的）。token 缓存超过
  `TOK_STALE` 则真的会让 `$/h`、out、hit、io、msgs 消失，才是 WARN。`.fail` 退避文件同样
  分两种：色板仍能上色时它不影响渲染，不能上色时才等于整行无色。CC Switch 库缺失、不可读、
  旧架构缺 `providers` 表都只是回落 `$x*`，一律 WARN。探针按渲染侧 `current_provider` 的
  列口径读 `id / limit_daily_usd / meta`，并复算 `limitDailyUsd`：有效 → PASS、**未设置 →
  SKIP**（日限额项本来就不显示，属正常配置，报 WARN 是噪音）、非法值或元数据损坏 → WARN。
  只 `COUNT(*)` 会把「缺列」「限额为 0」误报成「口径可确定」。后台刷新检查也按同一原则：
  python3 版本低于最低要求时 SKIP（根因已在 环境/python3 报 FAIL），不因为找到了 python3
  就 PASS。
- **git 缓存不报「超时」**：`GIT_TTL` 只有 5 秒，超过它是每次刷新的正常状态（后台会重算，
  同步路径也会回退到现算），报了等于每 5 秒一条噪音。doctor 只校验它的 4 段格式。
- **无 `.ts` 的旧 token 缓存报 WARN**（10-30 裁定，同日复审修正）：渲染侧本轮把它当「新鲜」
  沿用，但后台刷新会按缓存 mtime 补写 `.ts`（3a8679e），下一轮就判陈旧并隐藏派生项——
  「一直沿用、不会自动判陈旧」是错的。诊断抓的是刷新前这段静默陈旧，所以不降为 PASS。
  文案区分两种成因：`有 .ts 且过期` = 项已被隐藏；`无 .ts 且陈旧` = 本轮仍沿用、刷新回填后
  隐藏（不需要手工删）。
- **中转站判定要同时看 shell 与 `settings.json` 的 `env`**：CC Switch 的标准写法是把
  `ANTHROPIC_BASE_URL` 写进 settings 的 `env`，由 Claude Code 注入状态栏进程；因此 settings
  有值时**以它为准**，shell 里的同名变量只作回退（旧会话可能还留着官方地址）。只看 shell
  会在最常见的部署方式上得出相反结论（该报「中转站但没库」却报 SKIP）。订阅模式下不打开
  CC Switch 库，与 `statusline-tokens.py` 约束 7 一致。
- **冒烟用两份夹具做差分**：`CLAUDE_SL_TMP` 指向 mktemp 目录、`CLAUDE_SL_NO_REFRESH=1`、
  `COLUMNS=200`，要求两次结果**不同**且不是版本守卫的最简行。只看「非空」太弱——`echo hello`
  也会通过（复审实测）。**两份夹具在同一个目录里跑**，差异只来自 stdin 的
  `workspace.current_dir`、总输入 token、ctx / 模型 / 费用与 5h 额度；否则只 `printf "$PWD"`
  的占位脚本也会因为两次 `cd` 不同而「通过」（第二轮复审实测）。差分落在 dir 与 ctxin 上，
  因为这两项在默认序列里永不丢弃，所以即使用户 drop 了 ctx、模型与费用也不会误报；只有把
  包括 dir、ctxin 在内的显示项全部 drop 的极端配置才会误判。还要拒绝 stdin 原文：`cat`
  会把两份不同夹具原样输出，差分成立却没渲染（第三轮复审实测）。差分本身也不够：只提取
  几个字段的脚本（`jq -r .model.display_name`，或 model+ctx%）同样会通过，所以要求目录与
  ctxin 两项的渲染形态都出现——它们是默认不降级的两项；显式 drop 这两项的极端配置会误报。
- **不读用户会话内容**：`--transcript` 只检查该会话的 jsonl 是否可读；默认只做缓存目录的
  粗粒度统计（个数、最新写入时刻、格式、归属），不解析缓存内容——诊断不需要看你的用量。
- **判据保持多份实现，靠契约测试对齐**（10-30 裁定）：doctor 与渲染脚本各写一份 stat 包装、
  PKEY、色板首行、token 新鲜度、配置解析与 `points_to`。抽成共享 shell 文件能真正做到单一来源，
  但代价是分发契约多一个文件（已安装用户必须重装）、渲染同步路径多一次 source、共享文件还要
  兼容 bash 3.2（doctor 的要求低于渲染脚本的 4.2+），与本阶段「不重构」冲突。因此选择：
  - 常量与名单逐字比对：`THEME_TTL` / `TOK_STALE` / `STATUS_STALE` / `LOCK_STALE` /
    `PALETTE_V` / `TOK_FIELDS`、主题与胶囊风格白名单、官方地址白名单、bash 下限；
  - `CONF_KEYS` 与配置解析器的 case 分支比对；`step` 的合法项名直接读渲染脚本的 `ITEM_IDS`
    （取不到就跳过该项校验，不另抄一份）；
  - `points_to` 与 install.sh 同一实现方式：逐次剥离「文件名后紧跟单词字符」的出现，所以
    `.bak` 与真引用混在同一条命令里也能认出真引用；测试用多种写法验证两侧结论一致；
  - PKEY 测试先**真跑渲染脚本**生成色板缓存，再让 doctor 去找同一个文件名（不是测试自己编名字）；
  - `.ts` 的符号链接与损坏语义、无 `.ts` 时的处理都有对应用例；
  - 状态页缓存只读时间戳并与 `STATUS_STALE` 比对；`status_page = off` 与缓存缺失都 SKIP，
    不发起请求；锁按 `-L`、非空目录判故障（渲染侧只用 `mkdir` / `rmdir`，删不掉就永不自愈）；
  - CC Switch 限额探针是内嵌 Python 的第三份实现：测试对同一份 SQLite 夹具同时跑
    `statusline-tokens.py` 的 `current_provider` 与 doctor，锁死「PASS ⇔ 上游认为限额可用」。
  残余风险：测试没覆盖到的语义仍可能漂移，新增判据时要同时补契约测试。
- **诊断不进渲染路径**：`statusline-command.sh` 与 `subagent-statusline.sh` 都不引用 doctor，
  由静态测试守护；渲染的每次刷新没有任何新增成本。
- **默认不联网**：doctor 不调用 curl（测试用一个「被调用就留标记」的假 curl 验证）。状态页
  只读缓存的时间戳与 indicator，不主动拉取。
- **凭据过滤在显示层**：`scrub()` 抹 `sk-…` / `*_KEY=…` / `*_TOKEN=…`（大小写不敏感、值可带
  引号）/ URL 里的 `user:pass@` 与 query 参数值（`?token=…` / `&key=…`，参数名与其余结构
  保留）/ `x-api-key: …` / `Authorization: <scheme> …` / `Bearer …`，路径与其余参数保留
  ——不保留就没人能照着修。`ANTHROPIC_BASE_URL` 在中转站备注里只给 host；命令行原文保留
  scheme/host/path，但抹掉 query 与凭据。

## 缓存生命周期与兼容性（Phase 07）

- **面板状态并入主栏缓存根**（10-31）：原先面板把状态直接放在共享的
  `${TMPDIR:-/tmp}/claude-subagent-sl-<uid>.json`，与主栏的私有目录不在同一棵树里，`TMPDIR`
  未设时直接落在 `/tmp`。现在默认写 `${TMPDIR:-/tmp}/claude-sl-<uid>/claude-subagent-sl-<uid>.json`
  （需要时 0700 创建），设了 `CLAUDE_SL_TMP` 时跟随它——预览 / 测试只设一个变量就能同时隔离
  主栏与面板。`CLAUDE_SUBAGENT_SL_STATE` 仍是最高优先级的单文件覆盖。旧 `/tmp` 状态不迁移
  （只有速率基线，丢失代价是一帧）。
- **不抽共享缓存库**：两处路径解析各约 8 行，抽文件要多一份分发契约、多一次 source，
  共享文件还得同时满足 bash 3.2（doctor）与 4.2（渲染），收益不抵成本；改为两边各写一份，
  用契约测试锁住同源性（`test_panel_state_lives_in_cache_root` 等）。
- **读取一律拒绝符号链接**：`cache_ok` 从「可读 + 属于本人」收紧为「可读 + 非符号链接 +
  属于本人」，缓存根同样要求是本人拥有的真实目录。私有 0700 目录里本机他人建不了文件，
  但显式根 / 共享目录 / 预置链接仍可能指向别处；拒绝的成本是一次内建 `-L` 判断，不 fork。
- **不新增 `--cleanup` / `--prune` 命令**：后台刷新本来就在跑，加一条按需清理的公共命令
  会多出接口、文档与误删风险，却没有对应的可靠性收益。改为在 `--refresh` 末尾做一次
  **每天最多一次**的清理（用 `claude-sl-prune.stamp` 的 mtime 节流）。
- **清理策略保守到可以「删错也没事」**：只清默认根 `-maxdepth 1 -type f` 里的
  `claude-sl-tok-*.cache(.ts)` / `claude-sl-skip-*` / `claude-sl-git-*.cache` /
  `.claude-sl-*` 残留临时文件，阈值 30 天；不递归、不跟随符号链接（`-type f` 本身不匹配
  目录与链接）、不碰锁目录、色板、状态页、面板状态。显式 `CLAUDE_SL_TMP` 完全不清理——
  预览 / 测试目录的生命周期由调用方负责。所有被清对象都能重建，最坏结果是下一轮慢一次。
- **显式根不创建、不清理**（10-31 裁定，维持现状）：`CLAUDE_SL_TMP` 是预览 / 测试 / 高级
  用法，自动创建或清理都会动到调用方自己的目录。doctor 把「目录不存在」判 FAIL 并给出
  `mkdir` 命令；其余生命周期完全归调用方。
- **阈值保持常量**（10-31 用户裁定）：不新增 `cache_max_age` 配置键，也不加环境变量。
  30 天写死在 `CACHE_MAX_AGE`，README / DECISIONS 说明；需要调整就改常量重新安装。
- **会话状态另加 transcript 守卫**（10-31）：`claude-statusline-*.json` 是躲开整段重扫的
  断点，大 transcript 重扫要按 32 MB 分片慢慢追（可能数小时）。一刀切 30 天会让「隔月
  恢复的老会话」丢掉断点，因此只在它记录的 `files` 键**全部不存在**时才删；读不出
  （损坏 / 无 jq）按「无 transcript」处理（那种状态本来也会触发重扫）。修剪时只处理
  超过 30 天的少数文件，jq 只在后台每天跑一次。
- **清理与写入不加锁**（记录为有界风险）：修剪只碰 mtime 超 30 天且（对会话状态）
  transcript 已不存在的文件；活跃会话每 ≤15 分钟刷新，mtime 永远新鲜；已打开的 fd 在
  unlink 后仍能读完。最坏是并发时删掉一个正要被读的旧缓存，下一轮重建。
- **旧 `/tmp` 残留保持现状**（10-31 用户裁定）：旧版写在共享 `/tmp` 的 theme / git /
  status / 旧锁目录不自动删除、也不迁入私有根。迁移收益约一次色板重算，删除则可能让仍
  用旧副本的会话重建；`/tmp` 本身由系统清理。会话级 token / skip / 状态沿用既有的一次性
  迁移（见「缓存目录私有化」）。
- **Linux 实测与 CI 子集**（10-31 用户裁定）：Debian 12.15（bash 5.2.15、Python 3.11.2、
  非 root、GNU coreutils）在 Docker 里跑全量 **196 项通过**，唯一跳过的是「系统 bash 是
  3.2」那条 macOS 专用用例。CI 新增 `ubuntu-latest` 作业：语法检查 +
  `cache subagent freshness install doctor`（平台敏感的缓存 / 面板 / 时效 / 安装 / 诊断），
  完整套件仍由 macOS runner 覆盖。不把 macOS 测得的行为改成为 Linux 让路——先验证，
  发现差异再按「macOS 不减功能、Linux 尽力兼容」裁定。
- **bash 4.2 实测**（10-31）：在 Debian 12 里从源码编译 bash 4.2.0 后跑全量，发现一个真实
  的 4.2 差异——`printf -v var ''`（空格式）在 4.2 **不清空变量**（5.x 才赋空串），导致
  占位符 `-` 原样上屏（`5h -%`、`out -`、`hit -%`、`m-`，中转站费用也回落到 stdin 值）。
  全量首轮 7 项失败全部由这一处引起。修复：两处占位符清空改成 `printf -v "$v" '%s' ''`；
  新增静态回归测试 `test_no_empty_printf_v`（扫 `src/` 与 `tools/`，禁止空格式写法）。
  第二处差异：bash 4.2 的 `-nt` / `-ot` 只比较到**秒**，同一秒内切换分支会被当成「没变」，
  git 缓存沿用旧分支（macOS 的 5.3 精确到纳秒，所以一直没暴露）。修复：git 缓存判据从
  「HEAD 比缓存新」改为「HEAD 不比缓存旧」（`! -ot`），同一秒也重算；代价只是 HEAD / index
  刚改过后的一秒内后台多跑几次 git。修复后 4.2 全量 0 失败（见阶段记录）。
- **兼容性下限**：bash ≥ 4.2（关联数组）；换壳守卫此前只接受 ≥5 的替代，会把「机器上有
  4.2–4.4」误判为无替代并退化成最简行，现改为 ≥4.2，与 `install.sh` / doctor 的
  `BASH_MIN` 同源。python3 ≥ 3.9（`str.removesuffix`，`math.dist` 是 3.8），此前只有 doctor
  检查，`install.sh` 现在安装前也拒绝。`TMPDIR` 尾斜杠归一（`${TMPDIR%/}`），含空格 / 中文
  的路径有回归测试。`stat` 沿用「macOS 用 `/usr/bin/stat -f`，其余先 GNU 后 BSD」。
- **只读缓存根只降级、不报错**：目录不可写时同步路径仍读已缓存的值，`--refresh` 静默
  退出（不向状态栏输出任何错误），doctor 的 `缓存/后台刷新` 报 FAIL。测试同时锁住
  「只读根仍显示已缓存项」与「刷新 stderr 为空」。
- **面板锁自愈**（10-31 用户裁定）：面板写回失败会让速率段永久缺失，而面板原先把
  `rmdir` 作为唯一清除手段——锁目录非空、被普通文件或符号链接占住时永远清不掉。现在：
  锁路径被普通文件 / 符号链接占住 → 立即 `rm -f` 重试（这种占位不可能是进行中的锁）；
  残锁超过 5 秒 → `rm -rf`（含非空目录），不带 `-L`、只删这个锁路径本身，符号链接只删
  链接不删目标。主栏刷新锁不改（它已有 doctor 的 `缓存/锁` 诊断，且 `mkdir` + `rmdir`
  的语义足够）。doctor 增 `缓存/面板锁`：普通文件 / 符号链接 / 非空目录 FAIL，空锁超 5 秒
  WARN，`PANEL_LOCK_STALE=5` 与脚本同源（契约测试）。
- **诊断补一项**：`缓存/面板状态` 只判归属、类型与 0600 权限，不读内容；显式
  `CLAUDE_SUBAGENT_SL_STATE` 时报 SKIP（生命周期归调用方）。`缓存/token` / `缓存/git` /
  `缓存/色板` / `缓存/状态页` / `缓存/退避` 同步补符号链接分支。
