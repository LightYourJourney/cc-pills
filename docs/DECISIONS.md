## 架构

- **同步路径只读缓存，慢的都在后台**（08-19 方案 C）：git、transcript、色板、状态页由脱钩的
  `--refresh` 进程算；同步路径只调一次 jq，宽度计算与组装全用 bash 内建（约束 17）。目标
  <20 ms，hyperfine 实测约 18 ms，其中 bash 启动与 jq 占约 11 ms——数字随机器与负载变化，
  高负载机器上会成倍增加，比较时用同一台机器配对测。
- **不做系统性重构、不拆模块**（11-17）：同步 / 后台分离、单文件主渲染器、单次 jq、降级 +
  回填、私有缓存与原子写都有数据支撑；把主脚本拆成多个文件，要么每次渲染多一次 source，
  要么多一份分发契约。以后有人再提「拆模块」时先看这条。
- **判据单一来源：渲染脚本自述（`--facts`）**（11-17，取代 10-30「多份实现靠契约测试对齐」）：
  诊断、安装器与测试要用的配置解析结果、路径、阈值、版本下限、token 缓存格式、中转站判定，
  都由 `statusline-command.sh --facts` 按「键=值」报出，不在别处另抄一份。自述分支及其之前
  的代码保持 bash 3.2 可跑、没有副作用（约束 20）。**新增判据时先问「渲染脚本能不能自己报」。**
  有意仍是多份的：缓存根解析在三个分发脚本里各一份（见「不抽共享缓存库」）；token 缓存
  `.ts` 的新鲜度 doctor 自己判（它要扫全部会话）；stat 包装三处各一份。
- **外部输入一律按不可信处理**（约束 16 / 18）：stdin 的文本字段在 jq 里按 Unicode 剔除控制字符
  （含 C1——C locale 下 bash 的 `[[:cntrl:]]` 只认单字节），bash 侧再剔一遍；配置文件只按白名单
  逐行解析、从不 source，容忍 CRLF 行尾与开头的 BOM；git 调用带 `--no-optional-locks` 与
  `-c core.fsmonitor=false`（仓库 `.git/config` 里的 fsmonitor 命令不执行）。仓库配置的 clean filter
  仍可能在 status 刷新索引时执行——**维持现状**（11-20 用户裁定）：屏蔽它要先读出所有 filter 名再
  覆盖成 `cat`，会让 git-lfs 这类靠 filter 的仓库误报「已修改」、后台每轮多一次 git 进程；只有拷来的
  不可信仓库才有风险，这是所有带 git 信息的提示符共有的暴露面。
- **`status_page` 开关**：默认 `on`（每分钟请求一次 status.claude.com）；`off` 时零网络请求、不显示
  服务状态，给不需要外部请求或在隔离环境里跑的人用。
- **不抽共享缓存库**：主栏 / 面板 / `statusline-tokens.py` 的路径解析各约 8 行；抽文件要多一份
  分发契约、多一次 source，还得同时满足 bash 3.2 与 4.2，收益不抵成本。同源性由契约测试锁住
  （`test_panel_state_lives_in_cache_root` 等）。

## 缓存

- **私有目录**（10-29）：默认 `${TMPDIR:-/tmp}/claude-sl-<uid>`（0700），文件 0600。读取前校验
  「属于本人、是普通文件、不是符号链接」（`cache_ok`），缓存根同样要求是本人拥有的真实目录；
  写入一律 `mktemp`（O_EXCL）+ 原子 `mv`，Python 侧 `mkstemp` + `os.replace`。拒绝符号链接的
  成本是一次内建 `-L`，不 fork。
- **缓存内容不可信，覆盖到求值上下文**（11-17）：不只是值的字符集。凡是缓存里来的字符串要当
  变量名（`printf -v`、`${!v}`）或进算术展开（`$((…))` 会把内容当表达式求值，数组下标里的
  `$(…)` 会执行），都先按字符集校验。`[ … -gt … ]` 不求值，是安全的。色板值只收数字与分号，
  token 与 git 状态剔除控制字符。
- **token 缓存是带版本的「键=值」**（11-17）：首行 `TOK=<TOK_V>`，其后每行一个指标，键见
  `statusline-tokens.py` 的 `FIELDS`，拿不到的指标整行不写。渲染脚本按 `TOK_MAP` 取值，不认识的
  键忽略，新增指标只是多一行。版本号只在 bash 一处（`TOK_V`，经 `fmt=` 传给助手原样写回，做法
  同 `PALETTE_V`）；首行不符的缓存整份不读，等下一轮刷新重写。
  - 值只按生产者会写的形状收：字母数字加 `. $ /` 或「用尽」，不符的那一项按没有处理（给助手
    加新的取值形状时要同步放宽）。等级读入时不单独认，`pl` / `al` / `risky` 只认四个已知值，
    其余等同于没有。金额进算术前另拦多个小数点。
  - `FIELDS` 与 `TOK_MAP` 的一致性由 `tests/test_tokens.py` 用 `--facts` 报出的键名单比对，另有
    一条「刷新 → 渲染」的端到端用例。
- **token 缓存新鲜度**（10-29）：生产者写 `<cache>.ts`；超过 `TOK_STALE=900` 秒同步路径不读
  派生值（$/h、out、等级、hit、io、msgs、comp），只保留 stdin 的额度百分比。没有 `.ts` 的旧缓存
  按新鲜处理，但刷新会按它的 mtime 补一次 `.ts`，否则「无时间戳 = 新鲜」会让旧值永久留存。
  窗口一致性护栏：当前 q5 / q7 / sp < 100 时，缓存里的「用尽」不可能属于当前窗口，丢弃该等级
  与 out；`bad` + 真实倒计时（「很快用完」）保留。
- **会话状态带版本**：`$SLT/claude-statusline-<sid>.json` 只认自身的 `v`，与 `STATE_V` 不符即
  整体重扫（分片、后台）。落盘只跟进度走（11-17）：只在游标前进时落盘、只给刚扫过的文件重算
  指纹；约束 1（被杀只丢一片）不变。transcript 里形状不对的行按没有处理，不能让异常在游标
  落盘前抛出——那样每轮都从同一片重读、再死一次，该会话永久不出数。
- **面板状态并入主栏缓存根**（10-31）：默认 `${TMPDIR:-/tmp}/claude-sl-<uid>/claude-subagent-sl-<uid>.json`；
  设了 `CLAUDE_SL_TMP` 时跟随它，预览 / 测试只设一个变量就能同时隔离主栏与面板。
  `CLAUDE_SUBAGENT_SL_STATE` 是最高优先级的单文件覆盖。
- **显式根不创建、不清理**（10-31）：`CLAUDE_SL_TMP` 是预览 / 测试 / 高级用法，目录必须已存在，
  渲染不代为创建（doctor 判 FAIL 并给出 `mkdir` 命令），生命周期完全归调用方。
- **只读缓存根只降级、不报错**：目录不可写时同步路径仍读已缓存的值，`--refresh` 静默退出，
  doctor 的 `缓存/后台刷新` 报 FAIL。
- **生命周期清理**：不新增 `--cleanup` 命令；`--refresh` 末尾**每天最多一次**清理（`claude-sl-prune.stamp`
  节流），保守到「删错也没事」：
  - 只清默认根 `-maxdepth 1 -type f` 里的 `claude-sl-tok-*.cache(.ts)` / `claude-sl-skip-*` /
    `claude-sl-git-*.cache` / `.claude-sl-*` 残留临时文件，阈值 30 天；不递归、不跟随符号链接、
    不碰锁目录、色板、状态页、面板状态。这些都能重建，最坏是下一轮慢一次。
  - 会话状态另加 transcript 守卫：只在它记录的 `files` **全部不存在**时才删；读不出就保留——
    大 transcript 重扫要按 32 MB 分片追很久，隔月恢复的老会话不能丢断点。
  - 清理与写入不加锁（有界风险）：只碰 mtime 超 30 天的文件，活跃会话 ≤15 分钟就刷新一次；
    最坏是并发时删掉一个正要被读的旧缓存，下一轮重建。
  - 主栏 `put()`、`statusline-tokens.py` 的 `TMP_PREFIX`、色板与面板的临时文件名都落在 `.claude-sl-*`
    前缀下，契约测试逐个核对，所以写一半被杀的残留也会被收走。
  - 阈值是常量 `CACHE_MAX_AGE`（10-31 用户裁定），不加 `cache_max_age` 配置键或环境变量。
- **旧 `/tmp` 残留保持现状**（10-31 用户裁定）：旧版写在共享 `/tmp` 的 theme / git / status /
  旧锁目录不自动删、不迁入；会话级 token / skip / 状态在首次刷新时一次性迁入私有根。
- **git 缓存 TTL 5 秒**（`GIT_TTL`）：`.git/HEAD` / `index` 不比缓存旧（`! -ot`，同一秒也算）就立即重算。
  缓存键是路径的可逆转义；转义后超过 180 字节改为整条路径的 FNV-1a 64 位哈希 + 末段可读部分。
  不改成只哈希首尾片段：中段不同、长度与首尾相同的两条路径会撞键、显示别家分支（11-20）。
- **色板失败退避**：生成失败后 `THEME_TTL` 内不再重跑；成功 = python 正常退出且写出的首行相符
  （只看首行时，「首行相符、只是过期」的旧色板失败了也算成功，每轮刷新都会重跑 python）。

## 外观

| 版本 | 做法 | 结果 / 为什么被替换 |
|---|---|---|
| 早期 | 每组一种底色、告警时整块变色 | 同屏常有 4 个彩色胶囊，喧宾夺主 |
| 第七版 | 中性底，按 14% 混入 profile 背景 | iTerm 透明度只提亮默认背景（#1e1f29 → 实测 #272a36），胶囊几乎融进背景 |
| 第八版 | 全部同一种字色 | 相邻两项、相邻两胶囊都分不开 |
| 第九版（现行） | 统一表面色 + 标签着色 + 三级信息层次 | 主次分明；胶囊底色统一时靠文字层级区分 |

- **标签着色 + 主次分层**（10-28）：标签用组色（ctx 绿 / 额度紫 / 费用青 / 尾段弱化），降饱和、
  避开黄红色相，彩度封顶在告警色的 75%；主值加粗；语义色只给需要注意的那一项。
- **胶囊风格是配置项**：tint（默认）/ cool / jewel / glass / mono / pastel 六种看完 iTerm 实渲染
  后全部保留；tokyo-glass 融合三种方案（Tokyo Night 冷色 token、贴近背景的玻璃胶囊、三级层次），
  告警分两档：80–94% 柔和红，≥ `crit_at`（默认 95）或很快用完为强红。
- **可辨距离只约束基础表面色**（`MIN_PILL_DE = 12`）：各风格的组胶囊明度 / 彩度由风格定义，
  逐组提亮会把风格的明暗节奏抹平。
- **主值对比度下限 `MIN_CONTRAST = 4.5`**（WCAG AA）：中灰底上 7:1 无解；文字极性按胶囊实际明暗定。这条下限不再
  退让。
- **256 色**：xterm 色块六档 0/95/135/175/215/255（不等距）与 24 级灰阶各取最近，再按平方距离
  择优；按等距六档换算会把中性胶囊落到偏色的色块上（10-28）。

## 信息项与降级

- **永不丢弃**：dir、git、gitst、model、ctx、ctxin、q5、cache、hit、io。其余项按「降级序列」逐步
  丢弃 / 缩短；放得下之后按逆序回填（某一步一次省出很多列时，被牺牲的项能恢复）。额度进入风险
  态时其 drop 失效——免得只剩一个看不出属于谁的「out 1h42m」。
- 预算 = `COLUMNS − SAFE_MARGIN`（见「契约来源」）。宽度用 `dw` 的显示宽度模型算（约束 13）：三字节
  字符（CJK / 全角）2 列，脚本自己用到的三字节窄符号 1 列，双字节字符（西里尔 / 希腊 / 带重音的拉丁
  字母）1 列；模型只许偏宽、不许偏窄（宁可多降级，不溢出截断）。
- `misses` 不显示；墙钟时长不显示（含空闲），只显示 `api` 累计时长；宽屏填充只加消息数
  （`m517`），会话开始时刻、git 领先 / 落后都被否。
- ctx 阈值 70 / 90 与额度阈值 50 / 80 分开：ctx 是「快满了该压缩」，额度是「用得多了」。
  低信息量时隐藏：5h 的重置倒计时与整个 7d 只在已用 ≥ `WARN_AT` 或节奏告警时出现。
- **已用 ≥ 100% 判最高级并显示「用尽」**，不显示可能为负的「还剩」。额度百分比取整时未满 100
  的不进位（99.6 显示 99%），否则会显示 100 而后台按原始值还没用尽（11-15）。
- **$/h 半衰期 1200 s**（10-28）：单笔大请求的跳变压到 600 s 时的一半；滑动窗口被否（15 分钟窗更
  跳，30 分钟窗反应更慢）。数据见 HISTORY。
- **第三方模型名缩略**：无空格的名字取首个 `-` 段并保留方括号（`deepseek-flash[1M]` →
  `deepseek[1M]`）。代价：同家族 flash / pro 在窄屏最后一级会缩成同一个名字。
- **不加「今日」标签**：会话费用、速率、今日合计依次相邻，标签冗余；`spend_limit` 的「今日 / 本周
  / 本月」保留——那里标签表示周期。
- **示例配置不固化默认序列**（10-29）：示例里的 `step` 全部注释，没有 `step` 行时用内置
  `STEPS`；写一行就整体替换。注释里的顺序由 `tests/test_tokens.py::ConfigProtocol` 与 `STEPS` 对齐。

## 费用口径

- **自动分模式**：stdin 有 5h / 7d 额度 → 订阅；否则设了非官方 `ANTHROPIC_BASE_URL` → 中转站；
  都没有 → 订阅（订阅会话首个 API 响应之前还没有 `rate_limits`）。
- 订阅显示 `$x`：标价估算的等价价值。中转站显示 CC Switch 账本 + 未入账尾部，有未计价消息时
  加 `+` 表示下限；拿不到 CC Switch 数据回落 `$x*`。中转站读库失败时 `$/h` 隐藏——追踪器停在
  上一次账本读数，不能当现值输出。
- 网关 `rate_limits.spend_limit` 存在时优先于 CC Switch 的日限额。
- **「今日花费」按 `app_type = 'claude'` 直查数据库**：无头会话（`claude -p`）从不渲染状态栏，
  靠「渲染过的会话」列表会漏掉。Codex 等其它 app_type 不计入。
- **中转站日限额按「当前供应商可归属」口径**（10-29，上游 CC Switch v4.0.21 的
  `check_provider_limits` 核实，出处见 HISTORY）：今日用量 =
  `proxy_request_logs` + `usage_daily_rollups` 中 `provider_id = 当前供应商` 的和；限额读
  `providers.meta.limitDailyUsd`（旧库回落 `limit_daily_usd` 列）；`'_session'` 哨兵不归给任何
  供应商。有日限额时显示 `$cur/$限额`，全局今日由无日限额时的 today 项显示。没有 / 多个 `is_current`、限额非法或为 0 时隐藏日限额项与预测——未知不能当 0；
  供应商切换时 day 追踪器按（本地零点, provider_id）重置；「距重置」按下一个本地零点算（夏令时
  切换那天不是 86400 秒）。账本的几条 SELECT 在同一个读事务里。它是只读提示，不是硬预算。
- **只读打开 CC Switch 库**（`statusline-tokens.py` 约束 7）：URI 里的 `% # ?` 百分号编码，
  否则 `# ?` 会截断 `mode=ro`；订阅模式下根本不打开。

## subagent 面板

- **task id 只认字符串**（契约如此）：别的类型的 id 那一行不输出（回到默认渲染）、不写状态——拿它
  索引状态对象会让整个 jq 中止，连带别的行与写回一起丢。
- **面板 ctx 显式标「剩」**（10-29）：主栏 ctx 是已用，面板算出的是剩余（<20% ⚠），同名会误读。
- **共享状态加锁**（10-29）：状态文件被本机所有会话共享，读-改-写全程持 `mkdir` 锁，锁内重新
  读取后再合并；抢锁超过 1 s 就放弃本次写回——宁少一帧速率，也不覆盖别家条目。
- **残锁回收**（10-31）：锁里记 owner（PID.token），释放只删自己的锁；`mtime >= 5` 秒时 PID 还活
  着就放弃，PID 已死或 owner 缺失才 `rm -rf`（只删锁路径本身、不跟随链接）；锁路径被普通文件 /
  符号链接占住时立即 `rm -f` 重试。主栏刷新锁不同：不记 owner、目录只用 `rmdir`（只拦非空目录，
  超过 `LOCK_STALE` 的空锁仍会被抢）。
- **写回失败由面板自己记账**（11-08 用户裁定）：抢锁超时 / 合并失败 / 建临时文件失败 / 写入失败
  / 替换失败时往 `STATE.fail` 写一行 `epoch 原因码`（`busy` / `merge` / `tmp` / `write` / `mv`），
  成功写回时删掉。这个事实只在面板一处产生，诊断不再逆向推演锁目录。标记是尽力而为：目录不可写
  时连标记也落不下，由 `缓存/后台刷新` 报；空 stdin 与目录不可写都不抢锁、不记失败；标记路径是
  符号链接时先删再写，是真目录则不写。`mark_fail` 的临时文件落在 `.claude-sl-*` 前缀下，由每日清理收走。
- `subagent-statusline.sh --facts` 自述面板状态文件路径，诊断不另算。
- 旧 `/tmp` 面板状态不迁移（只有速率基线，丢失代价是一帧）。

## 安装

- **不自动改 `settings.json`**：install / check 只读 `statusLine` 与 `subagentStatusLine` 两个键并
  打印建议写法；uninstall 只警告仍指向已删除文件的键。这样 JSON 写坏、符号链接写穿这类风险整类
  不存在。
- **「指向已安装副本」的判定**（`tools/lib/points_to.sh`，安装器与 doctor 共用）：命令里有
  `<DEST>/<脚本>`（DEST 去掉尾斜杠），或 `${CLAUDE_CONFIG_DIR}` / `${CLAUDE_CONFIG_DIR:-$HOME/.claude}`
  （及 `~`、展开后的家目录写法）开头的建议写法；`${CLAUDE_CONFIG_DIR:-/别处}` 不算——变量未设时
  跑的是别处的脚本。只是文件名相同、路径不明按 rc=1 报出。`.bak` 等后缀黏住的文件名不算引用。
- settings.json 存在却解析失败时如实说它坏了，不报「尚未配置」——否则会引导用户再粘贴一个已有的键。
- **复制安装**：线上是独立副本，改仓库后要重跑 `install.sh`。覆盖前把不同的旧副本存为
  `<文件>.bak.<时间戳>`，**备份失败就不覆盖**该文件。面板脚本在 `--with-subagent` 或已经装过时
  安装——重装时一起更新，否则它悄悄停在旧版。
- 安装前按 `--facts` 报出的下限检查 bash 与 python3，不满足就一个副本都不装。

## 运行诊断（doctor）

- **结构**（10-30）：`tools/doctor.sh`（入口：共享状态、加载顺序、汇总）+
  `tools/doctor/{env,install,cache,data}.sh`（四组检查）。`install.sh --doctor` 只是 exec 别名：
  安装是写工具、诊断是读工具，分开才能从结构上保证只读。诊断不进渲染路径（静态测试守护），
  渲染的每次刷新没有任何新增成本。
- **保持 bash 3.2 可跑**：最坏环境里（PATH 里只有 macOS 自带 3.2）它仍要能回答「为什么状态栏
  退化成最简行」。
- **只读、不联网、不读会话内容**：不调用 curl（状态页只读缓存的时间戳与 indicator）；
  `--transcript` 只检查 jsonl 是否可读；缓存只做粗粒度统计（个数、最新写入、格式、归属）。唯一
  的写是冒烟用的临时目录（跑完即删）。
- **五个状态词**：PASS / WARN / FAIL / SKIP / UNKNOWN。SKIP = 不适用；UNKNOWN = 取决于运行时
  stdin（如计费模式）。没有「差不多正常」这种中间态。
- **FAIL 只留给「状态栏很可能不工作」**：环境依赖不满足、安装目录或副本缺失、settings
  缺失 / 不可读 / 非普通文件 / 语法错误 / 未指向、缓存根不可用、锁路径被非目录占住（主栏刷新锁
  另含非空目录）、显式 `--transcript` 不存在或不可读、冒烟失败。副本与仓库不一致、配置文件
  不可读、面板状态权限或类型不对是 WARN（能跑，只是跑的不是那一版 / 少一段）。
- **判「能不能用」而不是「新不新」**：色板能上色（主题部分相同且 `P_CTX` 合法）就是 PASS，
  chroma / 风格 / 格式版本不符只会触发后台重算；token 缓存超过 `TOK_STALE` 会让派生项消失，
  才是 WARN；无 `.ts` 的旧 token 缓存也报 WARN（刷新回填后才会隐藏，诊断抓的是这段静默陈旧），文案区分
  「有 .ts 且过期」（项已被隐藏）与「无 .ts 且陈旧」（本轮仍沿用、刷新回填后隐藏，不需要手工删）；
  `.fail` 退避文件只在色板不能上色时才等于整行无色。CC Switch 库缺失 / 不可读 / 缺表一律 WARN
  （只是回落 `$x*`）；限额探针就是 `statusline-tokens.py --provider-state`（与渲染共用 `limit_state`）：
  有效 PASS、未设置 SKIP、非法 WARN。python3 低于下限时后台刷新检查 SKIP（根因已在环境组报）。
  git 缓存不报「超时」（5 秒 TTL，超过是常态），只校验格式。
- **优先问已安装副本**：回答「装着的那一版会怎么做」；首行 `cc-pills-facts=<n>` 是格式版本，
  doctor 只认自己懂的那一版（`FACTS_V`），不认就问仓库源文件——以后给自述加键时 +1。
  - **答不出自述的副本一律不执行**（11-17；冒烟这一处 11-20 补上）：源码里没有自述标记的副本
    不跑 `--facts`，冒烟也不跑（报 SKIP，提示先重装）。这个文件名不专属于 cc-pills，旧版也不认
    `--facts`、不一定认 `CLAUDE_SL_TMP` / `CLAUDE_SL_NO_REFRESH`，跑它就破坏只读承诺。此时首行
    提示先重装，与格式版本有关的检查（token 缓存首行、色板首行的 `/vN`）不做——磁盘上的缓存是
    那份旧副本写的、它照常读。
  - 缓存根可不可用以自述的 `slt_ok` 为准，doctor 自己的几步判断只用来解释原因。
- **冒烟用两份夹具做差分**：`CLAUDE_SL_TMP` 指向 mktemp 目录、`CLAUDE_SL_NO_REFRESH=1`、
  `COLUMNS=200`，两份夹具**在同一个目录里跑**，差异只来自 stdin（目录、总输入 token、ctx /
  模型 / 费用、5h 额度）。通过需要同时满足：
  - 非空，且不是版本守卫的最简行（「模型 · ctx%」）；
  - 不含 stdin 原文（`cat` 透传两份不同夹具也会「不同」）；
  - 两份结果不同（`echo hello` 也「非空」）；
  - ctxin 的渲染形态必须出现，另外模型 / ctx% / 费用 / 目录**任一**出现（目录可能被
    `truncate_length` 截短，不绑定完整路径）。ctxin 在默认序列里永不丢弃，所以用户 drop 了 ctx、
    模型与费用也不会误报；只有连 ctxin 与其余可辨识字段全部 drop 的极端配置才会误报。
- **中转站判定同时看 shell 与 `settings.json` 的 `env`**：settings 有值时以它为准（CC Switch 的
  标准写法），shell 里的同名变量只作回退。算不算中转站由渲染脚本的自述判。
- **面板相关检查**：`缓存/面板锁` 只判锁路径是否被非目录占住（FAIL）与 `STATE.fail` 标记（WARN，
  含年龄与原因码；超过 `PANEL_FAIL_STALE` 视为此后没有写回尝试）；不读锁目录 mtime、owner 或
  PID。标记里的时间戳按不可信数据处理：非数字 / 读不出 / 写在未来都按「刚刚」，带前导 0 按十进制
  （`10#`）。`缓存/token` / `缓存/git` / `缓存/色板` / `缓存/状态页` / `缓存/退避` 都有符号链接分支。`缓存/面板状态` 只判归属、类型与 0600 权限，不读内容；
  显式 `CLAUDE_SUBAGENT_SL_STATE` 时两项都 SKIP。
- **凭据过滤在显示层**：`scrub()` 抹 `sk-…` / `*_KEY=…` / `*_TOKEN=…` / URL 里的 `user:pass@` 与
  query 参数值 / `x-api-key: …` / `Authorization: …` / `Bearer …`，路径与其余结构保留——不保留就
  没人能照着修。中转站备注里的 `ANTHROPIC_BASE_URL` 只给 host。

## 兼容性与 CI

- **bash ≥ 4.2**（关联数组）：版本守卫找常见位置的 ≥4.2 bash 重跑，找不到才退化成最简行；
  `install.sh` / doctor 的下限经 `--facts` 同源。4.2 与 5.x 的两个已知差异必须避开：
  `printf -v var ''`（空格式）在 4.2 不清空变量——一律写 `printf -v "$v" '%s' ''`，由静态测试
  `test_no_empty_printf_v` 禁止；`-nt` / `-ot` 在 4.2 只比较到秒——git 缓存判据用 `! -ot`。
- **python3 ≥ 3.9**（`str.removesuffix`）：安装前拒绝，doctor 报 FAIL。
- `TMPDIR` 尾斜杠归一（`${TMPDIR%/}`），含空格 / 中文的路径有回归测试；`stat` 用「macOS 用
  `/usr/bin/stat -f`，其余先 GNU 后 BSD」。
- **不为未验证的环境牺牲已验证行为**：先验证，发现差异再按「macOS 不减功能、Linux 尽力兼容」裁定。
- **CI 四个作业**（`.github/workflows/tests.yml`）：
  - macOS：全量。
  - Linux：全量 + shellcheck（11-17 起全量，取代 10-31 的子集）。shellcheck 为 warning 级，
    SC2034 / SC2154 整类关掉（变量靠 read 名单、`printf -v` 与跨文件 source 赋值）。
  - bash 4.2：源码编译 4.2.0（按版本缓存），放到 PATH 最前跑全量。源码包下载后先按固定 sha256 校验
    （11-20 用户裁定；值与 Homebrew 历史 bash 公式一致）。4.3 / 4.4 没有单独作业。
  - python 3.9：用 `PY_MIN` 版本跑全量（11-20 起；此前下限只在 README 里声明）。
  - 各作业 `timeout-minutes: 30`；测试里单次渲染 / 刷新另有 60 s 超时，挂住时用例失败而不是空等。
- **Linux 作业跳过并发写面板状态的用例**（10-31 实测）：`ubuntu-latest` 上两个独立进程能在约 2 µs
  内**都** `mkdir` 同一条路径成功，本地 Debian / Ubuntu 容器复现不出。Linux 作业设
  `CCPILLS_SKIP_CONCURRENCY=1` 跳过 `test_concurrent_writes_do_not_lose_entries`，该用例由 macOS 全量
  覆盖；锁语义没有为这台 runner 改写。证据细节见 HISTORY。

## 测试

- **验收标准是变异，不是用例数**（11-17）：补网时先在仓库副本上做单点变异，确认每个变异都有
  一条用例能发现才算数；修 bug 先写在旧代码上失败的用例。
- **不加时钟注入之类的测试专用入口**：后台刷新的时间戳都在缓存文件内容里（git 缓存第 4 段、
  `.fail`、skip 文件、状态页缓存），锁的年龄是 mtime，都能直接构造「过去」来测。
- **全量默认并行**（11-20）：`tests/_parallel.py` 把用例按轮转切成 min(核数, 8) 片、每片一个进程；
  对时序敏感的 tokens（共享时间预算）与 subagent（并发抢锁）之后串行跑；`test_*.py` 没归到任何一段
  时直接失败。`CCPILLS_SERIAL=1` 回到串行。
- 常量与名单从代码取（`--facts`、`FIELDS`、`STYLES`、示例配置），不在测试里另抄一份。
- 每个渲染用例在独立沙箱里跑（`tests/_util.py`：私有缓存根、XDG 配置、固定 locale、预置状态页
  不联网、倒计时留 +30 s 余量）。
- 预览工具（`tools/preview.sh`）同样隔离：每次用独立缓存目录 + 假数据，跑完即删（早期版本把伪造的
  「claude major」写进了全会话共享的状态缓存）。

## 被否掉的假设

- **「两源重复记账」**：15 个两源并存的会话逐条比对，残余重复为 0。代理行与会话日志行互补。
- **「会话日志滞后 9 小时」**：实为使用者空闲；日志每 10 分钟同步。
- **`prompt_cache.warm = false` 就判冷**：它也包括「最近一次响应没报告缓存 token」，所以只在
  `expires_at` 已过时判冷。
- **「拆模块能让主脚本更好维护」**：见「架构」。

## 与 Claude Code 的契约来源

- stdin schema：`claude --version` 对应的二进制与官方 statusline 文档（v2.1.311 实测）。
- `rate_limits.spend_limit`：Claude Code 2.1.312 二进制核实，含 `used_percentage`（可 >100）、
  `resets_at`、`used_usd` / `limit_usd`（可选）、`period`（daily / weekly / monthly）。
- `SAFE_MARGIN = 4`：截图反推——`COLUMNS=146` 时 141 列内容 + 「…」被截断，故可用宽度为
  `COLUMNS − 4`；歧义宽度字符按 1 列计与截断点吻合。

## 版本与发布

- `VERSION` 写在 `statusline-command.sh` 一处，与 git tag `v<版本>` 对应，经 `--facts` 报出；
  doctor 首行打印已安装副本的版本，与仓库不同时两个都给。发布时改这个常量并打 tag。
