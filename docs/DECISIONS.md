# 设计裁定与沿革

脚本头部只留「改代码时必须知道的契约」。这份文件记录**为什么长成这样**：每次外观改版、
每项去留的裁定、做过又否掉的假设。改外观或降级序列前先读这里，免得把已经否掉的方案
再提一遍。

日期均为 2026 年。

## 架构

- **08-19 方案 C**：同步路径只读缓存 + 后台刷新算慢的（git / transcript / 配色 / 状态页）。
  当时的目标是 <20 ms；10-28 实测中位约 18–22 ms（视降级步数）。
- 同步路径只允许一次 jq；宽度计算与组装全在 bash 内建完成（约束 17）。
- **状态文件带版本**：`$SLT/claude-statusline-<sid>.json` 只认文件自身的 `v`；与 `STATE_V`
  不符即整体重扫（分片、后台），旧结构不会被当成新结构读。v9 把每文件消息数键改为
  `last_id` / `msgs`。
- **缓存目录私有化**（10-29）：默认 `${TMPDIR:-/tmp}/claude-sl-<uid>`（0700），文件 0600；
  读取前用 bash 内建 `-O` 校验所有者，跨用户预置的同名文件一律不读；临时文件用 `mktemp`
  （O_EXCL），Python 侧用 `mkstemp`。旧版 `/tmp` 的本会话 token / 状态 / 跳过标记在首次
  刷新时迁入私有目录。缓存内容按不可信数据处理：token 字段剔除控制字符，色板值只接受
  数字与分号，git 状态也剔除控制字符。显式 `CLAUDE_SL_TMP`（预览 / 测试）由调用方负责
  隔离；旧 `/tmp` 里的历史文件不自动删除（过渡期残留，由系统清理或用户手工删）。
- **18 段 token 缓存的字段顺序以 `statusline-tokens.py` 的 `FIELDS` 为准**：生产者按字段名
  填、按 `FIELDS` 输出；bash 的 `IFS=tab read`、测试与 `tools/preview.sh` 的假数据由
  `tests/test_tokens.py` 的契约测试守护。改顺序只动 `FIELDS` 与 `BASH_NAMES`。

## 外观沿革

| 版本 | 做法 | 结果 / 为什么被替换 |
|---|---|---|
| 早期 | 每组一种底色、告警时整块变色 | 同屏常有 4 个彩色胶囊，喧宾夺主 |
| 第七版 | 中性底，按 14% 混入 profile 背景 | iTerm 透明度只提亮默认背景（#1e1f29 → 实测 #272a36），胶囊几乎融进背景 |
| 第八版 | 全部同一种字色 | 相邻两项、相邻两胶囊都分不开 |
| 第九版（现行） | 统一表面色 + 标签着色 + 三级信息层次 | 主次分明；胶囊底色统一时靠文字层级区分 |

## 外观裁定

- **标签着色 + 主次分层**（10-28）：标签用组色（ctx 绿 / 额度紫 / 费用青 / 尾段弱化），
  降饱和、避开黄红色相，彩度封顶在告警色的 75%；主值加粗；语义色只给需要注意的那一项。
- **胶囊风格做成配置项**：先做了 A–F 六种（tint / cool / jewel / glass / mono / pastel），
  看完 iTerm 实渲染预览后全部保留为 `pill_style` 的可选值，默认 `tint`。
- **tokyo-glass**：融合 B/C/D 三种方案——Tokyo Night 冷色 token、贴近背景的玻璃胶囊、
  三级层次；模型名冷蓝、费用降为二级不加粗、hit/io/api 降为三级。告警分两档：80–94%
  柔和红，≥ `crit_at`（默认 95）或很快用完为强红。
- **胶囊底色与背景的可辨距离只约束基础表面色**（`MIN_PILL_DE = 12`）：各风格的组胶囊
  明度 / 彩度由风格定义，不再逐组套这道门槛。原因是逐组提亮会把风格设计的明暗节奏
  抹平（外观裁定优先于统一门槛）。
- **中灰底上 7:1 无解**：主值退到 `MIN_CONTRAST = 4.5`（WCAG AA）。10-28 对比度矩阵复测
  时发现中灰底上文字极性判错（浅字压在亮胶囊上只有 3.76），已改为按胶囊实际明暗定极性；
  4.5 这条下限不再退让。

## 信息项去留

- **永不丢弃**：dir、git、gitst、model、ctx、ctxin、q5、cache、hit、io。
- 其余项按「降级序列」逐步丢弃 / 缩短；额度进入风险态时其 drop 步骤自动失效——免得
  只剩一个看不出属于谁的「out 1h42m」。
- `misses` 不显示（无效信息）；墙钟时长不显示（含空闲时间），只显示 `api` 累计时长。
- ctx 阈值 70 / 90 与额度阈值 50 / 80 分开：ctx 是「快满了该压缩」，额度是「用得多了」。

## 费用口径

- **自动分模式**：stdin 有 5h / 7d 额度 → 订阅；否则设了非官方 `ANTHROPIC_BASE_URL`
  → 中转站；都没有 → 按订阅处理（订阅会话在首个 API 响应之前还没有 `rate_limits`，
  曾因此被误判成中转站）。
- 订阅显示 `$x`：标价估算的等价价值，不加 `API≈` 前缀。
- 中转站显示 CC Switch 账本 + 未入账尾部；有未计价消息时加 `+` 后缀表示下限。
- 网关 `rate_limits.spend_limit` 存在时优先于 CC Switch 的日限额。
- **「今日花费」按 `app_type = 'claude'` 直查数据库**，不再依赖「渲染过状态栏的会话」列表：
  `claude -p` 等无头会话从不渲染，靠列表会把它们的花费永久漏掉（实测漏了一个 $0.28
  的会话）。Codex 等其它 app_type 不计入，需要看合计时去 CC Switch 用量页。
- **中转站日限额按「当前供应商可归属」口径**（10-29，上游核实）：CC Switch v4.0.21 的
  `check_provider_limits`（`src-tauri/src/services/usage_stats.rs`）把今日用量算成
  `proxy_request_logs` + `usage_daily_rollups` 中 `provider_id = 当前供应商` 的和；限额读
  `providers.meta.limitDailyUsd`（旧库的 `limit_daily_usd` 列已不被上游读取）。
  `provider_id = '_session'` 是会话日志的哨兵（`session_usage.rs`），上游也不把它归给任何
  供应商。故日限额的分子只算当前供应商可归属的今日；全局「今日」仍按 app_type 汇总。
  没有 / 多个 `is_current`、限额值非法或为 0 时隐藏日限额项与预测——未知不能当 0；供应商
  切换时 day 追踪器按（本地零点, provider_id）重置。上游此版本没有额度强制与 UI 消费
  （`useProviderLimits` 只有定义），所以它是只读提示，不是硬预算。
- **已用 ≥ 100% 判最高级并显示「用尽」**，不再显示可能为负的「还剩」。

## 速率与缩略（10-28 第二轮）

- **$/h 半衰期 600s → 1200s**。用本会话 601 条账本逐分钟重放：600s 时单笔大请求会让读数
  一分钟内跳 $14（一天 2 次 >$8），1200s 把最大跳变压到 $7.2、>$8 的跳变归零；代价是
  达到 90% 的时间从约 30 分钟变成约 50 分钟。**滑动窗口被否**：15 分钟窗反而更跳（单笔
  花费进出窗口即阶跃，>$3 跳变 8 次），30 分钟窗与 20 分钟 EWMA 相当但反应更慢。
- **第三方模型名缩略**：无空格的名字取首个 `-` 段并保留方括号上下文标记
  （`deepseek-flash[1M]` → `deepseek[1M]`，`gpt-6.1-sol` → `gpt`）。已知代价：同一家族的
  flash / pro 会缩成同一个名字，宽屏下仍显示全名，只有窄屏最后一级受影响。
- **宽屏填充只加消息数**（`m517`）：会话开始时刻、git 领先/落后都被否；墙钟时长维持
  早先「不显示」的裁定。
- **去掉「今日」标签**：会话费用、当前速率、今日合计依次相邻，标签是冗余；日限额与今日
  合计都改为只显示 `$x` / `$x/$限额`。`day` 项因此只剩一种写法，随之删掉 `shrink day`
  这一步。网关 `spend_limit` 的「今日 / 本周 / 本月」保留——那里标签表示周期。

## 被否掉的假设

- **「两源重复记账」**：15 个两源并存的会话逐条比对，残余重复为 0。两源（代理行、
  会话日志行）互补，不需要额外去重。
- **「会话日志滞后 9 小时」**：实为使用者空闲；日志每 10 分钟同步。
- **`prompt_cache.warm = false` 就判冷**：官方说明里 `warm=false` 也包括「最近一次响应
  没报告缓存 token」，所以只在 `expires_at` 已过时判冷。

## 交互与工具

- **预览工具必须隔离**：早期版本把伪造的「claude major」写进全会话共享的状态缓存，
  所有窗口跟着显示，而且旧的「上次拉取时刻」会让预览要等 30 秒。现在每次预览用独立
  缓存目录 + 假数据，跑完即删。
- **fit 回填**：降级时某一步可能一次省出很多列（如缩短长模型名），放得下之后按逆序把
  被牺牲的项恢复回来。
- **git 缓存 TTL 5 秒**：更短的等待换来分支切换后几乎立刻正确；`.git/HEAD` / `.git/index`
  变新时立即重算，不等 TTL。
- **`status_page` 开关**：默认 `on`（每分钟请求 status.claude.com）；`off` 时零网络请求、
  不显示服务状态。给不需要外部请求、或在隔离环境里跑的人用。
- **面板共享状态加锁**（10-29）：状态文件被本机所有会话共享，读-改-写全程持同一把
  `mkdir` 锁，锁内**重新读取**后再合并；抢锁超过 1s 就放弃本次写回（宁少一帧速率，
  也不覆盖别家条目）。残锁 5s 后清除。状态文件默认带 uid（
  `${TMPDIR:-/tmp}/claude-subagent-sl-<uid>.json`）、0600；旧状态不迁移（只有速率基线，
  丢失代价是一帧）。

## 与 Claude Code 的契约来源

- stdin schema：`claude --version` 对应的二进制与官方 statusline 文档（v2.1.311 实测）。
- `rate_limits.spend_limit` 字段：Claude Code 2.1.312 二进制核实，含 `used_percentage`（可 >100）、
  `resets_at`、`used_usd` / `limit_usd`（可选）、`period`（daily / weekly / monthly）。
- `SAFE_MARGIN = 4`：截图反推——`COLUMNS=146` 时 141 列内容 + 「…」被截断，故可用宽度为
  `COLUMNS − 4`；歧义宽度字符按 1 列计与截断点吻合。
